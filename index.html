What's happening
  • Your browser sends a DNS-over-HTTPS (RFC 8484) query to Cloudflare's 1.1.1.1 resolver. The lookup is encrypted inside TLS instead of travelling as plaintext UDP on port 53.
  • The recursive resolver walks the hierarchy for you: root servers → the TLD (.com) → the domain's authoritative nameservers. It then caches the answer for its TTL.
  • A/AAAA map names to IPv4/IPv6, CNAME aliases one name to another, MX routes email, NS delegates authority, TXT carries SPF/DKIM and verification tokens, and CAA restricts which CAs may issue certificates.
  • "DNSSEC validated" means the resolver verified the answer's cryptographic signature chain.

    What's happening
    • Handshake: SYN → SYN-ACK → ACK synchronises each side's random initial sequence number (ISN). SYN and FIN each consume one sequence number.
    • Reliable delivery: data is cut into MSS-sized segments. The receiver's cumulative ACK names the next byte it expects, and a missing ACK triggers retransmission of the same sequence range.
    • Teardown: each direction closes separately (FIN/ACK twice). The side that closes first sits in TIME_WAIT for 2×MSL so delayed packets can't corrupt a future connection.
